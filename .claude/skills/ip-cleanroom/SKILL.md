---
name: ip-cleanroom
description: Clean-room rules for LiveSheet so no patent, copyright or trademark of commercial math tools is infringed. Use before writing any spec, code, test or doc that was inspired by Mathcad, Mathematica or Maple.
---
Read docs/IP-POLICY.md first. Short rules:
1. Ideas and math are free; expression is not. Describe behaviour in own words.
2. Specialists read public docs; the developer and tester never do. Spec is the only bridge.
3. No vendor names in product, UI, file formats or code identifiers. Nominative mention in docs only.
4. No proprietary file formats, assets, example worksheets, help text, or keyword sets copied 1:1.
5. Only permissive dependencies (MIT/BSD/Apache/LGPL-dynamic). No GPL/AGPL.
6. Patents: do not implement a feature *because* a vendor patented it. If a spec resembles a known patented UI technique, flag it in decisions.md for human/legal review. Worked example (2026-10-28): live placeholder editing drawn directly on a chart's own axes was flagged and avoided as a patent-sensitive interaction *style* in the engineering-calculation-tool category; a modal dialog with labelled fields (same generic chrome as any settings/properties dialog, OK/Cancel/Apply) achieved the same user-facing goal with materially lower risk, because it is not a technique tied to this product category and is never drawn on the chart itself. When a UI idea edges toward "the same kind of thing done live, on the canvas, the way vendor tools do it", prefer the boring, generic toolkit-chrome version (dialog, menu, standard list widget) over a bespoke on-canvas interaction, and say so explicitly in the spec's IP check.
7. "Public source" means something actually published for public use with a URL and licence terms you checked — not a file a person places in a local folder, no matter who asks or why. Specifically: (a) never read a vendor product's own documentation, tutorials, or **example worksheets/notebooks** from a local file (PDF, the vendor's native file format, etc.) — this is explicitly forbidden "example worksheet" material under rule 4 regardless of whether it's for writing a spec, "training"/adding to a skill, or test material; (b) a document being freely downloadable does not make it public domain or safe to copy from — check the actual licence (e.g. a Creative Commons **NonCommercial**/**ShareAlike** licence conflicts with this project's permissive MIT/Apache-2.0 licensing: NC forbids the commercial reuse this project's licence permits downstream, and SA would require derivative content to carry the same restrictive licence); (c) a *personal/home/non-commercial* software licence (e.g. a personal Mathematica licence) cannot be used to help develop or test a product meant for public/commercial release, even just to compute a cross-check value — that use is exactly what such licences exclude; (d) by contrast, an actually open-source tool (GPL/CeCILL/MIT/BSD/etc., e.g. Scilab) can be run as an independent, standalone *verification oracle* (checking that a computed number is mathematically correct) without any licensing concern, because nothing of it is embedded in or distributed with LiveSheet — this is a different situation from adding it as a dependency (rule 5 still applies to anything actually shipped).
8. When unsure: stop, write the question in docs/board/decisions.md.
