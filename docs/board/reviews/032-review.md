# Review: spec 032 LaTeX in text regions, phase L1

Tester, 2026-11-12. Tests: tests/test_spec032_review.py (scanner, parser, Qt-free; 77 tests, 1 strict xfail) and tests/test_spec032_gui_review.py (region, PDF, colour, limits, click-to-caret; 102 tests). Full suite: 3751 passed, 2 skipped, 12 xfailed (includes the other tester's spec 031 files; no unrelated failures seen). Black-box from the spec; developer tests not copied.

## Verdict
L1 acceptance criteria 1-13, 15-27 pass. No crashes, no non-TexError escapes (5000 parser fuzz, 1000 layout fuzz, hostile region contents, injected internal errors). Raw source is preserved byte for byte through display, edit and leave cycles, and through file save/load. Defects below are ranked; none blocks L1.

## Defects (ranked)
1. MEDIUM, wrong glyph convention for common Greek letters. tables.py maps \phi to U+03C6 and \varphi to U+03D5 (also \epsilon to U+03B5, \varepsilon to U+03F5). That is the Unicode-math-package convention. In the system math font used here (rendered check, scratchpad greek2.png) U+03C6 shows the open-curl form and U+03D5 the closed stroked form, so \phi draws what LaTeX users know as \varphi and \epsilon draws what they know as \varepsilon. The spec lists only "\alpha..\omega" plus the \var variants and gives no code point table, so it is not a spec violation, but the spec says names follow ordinary LaTeX notation, and users will compare to LaTeX output. Recommendation: follow TeX appearance: \phi -> U+03D5, \varphi -> U+03C6, \epsilon -> U+03F5, \varepsilon -> U+03B5. Check against the bundled STIX font in L2, since glyph shapes differ per font. test_phi_varphi_mapping_documented only asserts the two differ and are Greek phi forms.
2. LOW-MEDIUM, scan() is quadratic for many unmatched single "$" openers on one paragraph. `"$a " * 8000` (24 kB paragraph) takes about 3.3 s, 20000 repeats take 20 s (each opener scans to end of paragraph because a closer after whitespace is invalid). 600-char paragraphs are instant, so it only bites on pasted bulk text; but scan also runs on every enter/leave and debounce, so it would freeze the UI. Fix: remember the position of the last failed scan for the paragraph (if no valid closer exists after position p, none exists for later openers either, except the digit/space rules, so cache "no closer from here"). Strict xfail: test_scan_many_unmatched_openers_is_fast.
3. LOW, accessibility (spec section 10): no accessible text exposing the raw source was found (grep for accessible in regions.py/texlayout.py empty); in display state the document holds U+FFFC placeholders. Not testable offscreen; flag for L2/manual check.
4. LOW, cosmetic layout seen in renders (scratchpad r/*.png): prime on a function name (`f'(x)`, `g''_i`) floats very high and touches the f hook; `f(x)` italic f collides with "("; in display `\int_0^\infty` the infinity limit nearly touches the integral sign; braces from `\left\{ \right\}` sit tight against neighbours; display integrand to "=" gap after `dx` is small. Everything else (inline scripts, fractions, nested fractions, binomial, radicals incl. index, sums with limits above/below in display and at the side inline, delimiters stretched as paths, error rendering, tint, caption) looked correct and crisp, also at 2x zoom in the real window.
5. LOW (spec ambiguity), the caption says "character N" as offset+1 (1-based) and "formula N" counts all spans including valid ones. Reasonable and consistent with the spec example; the manual should state it. A multi-paragraph/display-math error offset is relative to the formula source, not the region.
6. INFO, plain regions with no valid span keep the existing behaviour (text() returns the editor's normalised toHtml, not the original string). Byte-identical applies to regions that contain spans/escapes, which is what criterion 20/21 require. A region whose raw HTML is not Qt-normalised and has no math is therefore normalised on first text() call as before this feature.

## Developer deviations judged
- Caption numbering "formula N" over all spans, character 1-based: accepted.
- Greek mapping: see defect 1; recommend following TeX.
- Fixed glyph-box fractions (constants as fractions of font size): accepted; relations the spec tests (width ratio within 5%, rule between num/den, script 70%/50%, 6 pt floor) all pass. Script size floor is in pixels (8 px).
- QPyTextObject as inline object: accepted. Raster-free (no QPixmap/QImage in texlayout, PDF has /Font entries and no /Subtype /Image), exceptions in drawObject are caught. One caveat: the object height is derived from ascent/descent so a tall inline formula grows only its line (tested: short inline formula changes height < 8 px, plain regions identical to baseline).
- Error caption/tint hidden when sheet.printing; the invalid span prints in the error colour: verified by pixel test.
