# 005 Placeholder slots for plot regions

Source inspiration (concept only, nothing copied):
- https://developer.mozilla.org/en-US/docs/Web/HTML/Attributes/placeholder (general, vendor-neutral web-platform documentation, public, 2026-10-28). Concept taken only: an empty input field can show greyed-out hint text describing what belongs in it until the user provides a value. This is a generic, widely known UI pattern used across web forms, spreadsheets and countless editors; it is not specific to any one engineering-calculation product.
- No Mathcad, Mathematica, Maple or other vendor software, documentation or screenshot was read or consulted for this spec, per the task's instruction. No vendor product's placeholder-widget appearance, icon, colour, cursor glyph or exact click/keystroke sequence is described or used anywhere below. Slot layout, navigation order, commit keys, unit-control design and error-display rules are our own invention.
- Note for the manager/IP reviewer: spec 004's IP check explicitly recorded that placeholder-based axis editing was "deliberately NOT used" for phase A, to stay clearly on the safe side of a known interaction *style* in this product category. This spec revisits that only because Theo (the product owner) asked for it directly, after using the text-only editor himself; it is a product decision, not a copying decision. Per IP-POLICY.md rule 6, flag this interaction *technique* (not the generic hint-text idea) for a human/legal patent check before shipping — see Open questions.

Interop: this is a GUI-only presentation layer on top of spec 004 (phase A). It does not change `livesheet/engine/plotting.py` (`PlotTrace`, `PlotData`, `nice_axis`, `build_plot`) and does not change `livesheet/document.py` (`RegionData` keeps storing `text` + optional `w`/`h`; `FORMAT_VERSION` stays as spec 004 left it). A plot built through slots compiles to exactly the same plot-spec text spec 004 already parses, so every acceptance criterion of spec 004 (1-27) keeps holding unchanged; this spec only adds criteria for the new editing surface. One optional, additive engine helper is discussed under Open question 1; it is not required for phases C1/C2.

Size: three slices of 1.5-2 days each, about 5-5.5 days total.
- **Phase C1 (slot layout and basic editing)**: the y-slot(s), the x-slot, the trailing empty slot, click-to-edit, keyboard navigation and commit, compiling to the existing text format. About 2 days.
- **Phase C2 (unit controls and raw/text fallback)**: the x/y unit controls (`xunit`/`yunit`), detecting when a stored text spec fits the slot model, and the raw/text advanced-mode toggle. About 1.5 days.
- **Phase C3 (per-slot error display)**: attributing an error message to the slot that caused it, and the "waiting for x" state. About 1.5-2 days, and its exact scope depends on Open question 1. Phase C3 starts after C1/C2 are merged.

## User story
As an engineer placing a plot, I want to click directly on an empty spot near the y-axis and type the expression I want to see, and click on an empty spot near the x-axis and type or pick the variable it runs over, instead of writing the whole plot as one block of text. I want to add a second curve by clicking the next empty spot, see at a glance which line has a mistake without losing the others, and still have access to the full text view for things that do not have their own spot yet.

## Behaviour (own words)

### Fresh plot region
Inserting a plot (`Insert > Plot`, or the canvas "Plot here" entry) creates a region with exactly two things visible and nothing else: one **y-slot**, an empty field with a short hint (something like "y: expression"), positioned in the top-left corner inside where the chart's plotting area will later be; and one **x-slot**, an empty field with a short hint (something like "x: variable or range"), centred below where the x-axis will later be. No frame, axis lines, ticks or grid are drawn yet, and no error message appears — this replaces today's single `plot\nover \nshow ` starter text and its one hint message.

### y-slots: one field per trace, plus a trailing spare
The y-slots are stacked in a vertical column at the top-left of the chart area, one per trace, in the same top-to-bottom order as the `show` lines they compile to. At all times there is exactly one more empty y-slot than there are filled ones (the "trailing slot"), up to the existing 20-trace cap (spec 004); once 20 are filled, no 21st slot is offered. A trace is added simply by typing into the trailing slot and committing it, which turns it into a filled slot and creates a new trailing slot below it. A trace is removed by clearing its slot's text to empty and committing while it is not the trailing slot; the slots below shift up to close the gap. There is no separate add/remove button (see Open question 6).

### x-slot: variable, private range, and unit
The single x-slot accepts the same text spec 004 already accepts after the word `over`: either the name of an existing range variable or vector defined above the plot (`t`), or a private sampling range (`x from 0 to 6.28 points 100`). Once the x-slot (and at least one y-slot) are valid, a small **unit control** appears at the far end of the x-axis showing the current display unit (blank/dimensionless shows as empty); clicking it opens a one-line field equivalent to an `xunit` line — typing a unit and committing sets it, clearing it back to empty removes the override and the axis reverts to spec 004's automatic-unit rule. A matching unit control appears near the top of the y-axis for `yunit`, shared by all traces (they already share one y axis in spec 004). Unit controls are not part of the main slot list; they are reached by a direct click, not by Tab (see Keyboard navigation).

### Click-to-edit and commit
Each slot (y-slot, trailing slot, x-slot) is edited on its own: clicking it starts editing just that one field, exactly as double-click starts editing today's whole spec, but scoped to the one slot. A slot commits its text (and recompiles the plot, see Mapping) when: Enter is pressed, Tab or Shift+Tab moves focus away, the user clicks a different slot, or the user clicks anywhere outside the plot region (the existing `focusOutEvent -> finish_editing` rule, scoped per slot). Esc reverts only the slot being edited to its last committed text and ends editing of that slot; it never discards other slots' committed content. A slot never contains more than one line: Enter commits and moves on, it does not insert a newline (unlike a math region).

### Keyboard navigation between slots
Tab moves forward through the slots in a fixed order: y-slot 1, y-slot 2, ..., the trailing empty y-slot, the x-slot, and back to y-slot 1 (wrapping). Shift+Tab moves backward through the same order. The Up/Down arrow keys additionally move between adjacent y-slots (and the trailing slot) when the text cursor is already at the very start (Up) or very end (Down) of the slot's text, so normal left/right and up/down text-cursor movement inside a longer slot's text is unaffected. Unit controls are reached only by clicking them directly, not by Tab/arrow navigation, to keep the main slot order short and predictable.

### Mapping to the existing text format and engine
A slot-edited plot still compiles, internally, to exactly the text spec 004 already parses: the line `plot`, then one `over ...` line built from the x-slot, then one `show ...` line per filled y-slot in on-screen order, then an `xunit ...` line if the x unit control has a value, then a `yunit ...` line if the y unit control has a value — always in that order. This text is what gets stored in `RegionData.text` (no document-format change) and handed to `Engine.evaluate`/`build_plot` (no engine change in phases C1/C2); the chart drawing itself (`paint_plot`) is unaffected, slots are drawn as an editing overlay on top of (or instead of, when the plot is not yet valid) the chart.

A region whose stored text already uses lines without a slot (`title`, `xlabel`, `ylabel`, `xlim`, `ylim`, or more than one `over`/no `over`/anything spec 004's phase B will later add) cannot be fully represented by slots. Such a region opens in the existing full-text "raw" view instead of slots (see Advanced/raw mode) — nothing is silently dropped.

### Advanced/raw mode
A small control on the region (own design; exact look is an implementation detail, not specified here beyond "a clearly clickable corner control", see Open question 2) switches a plot region to spec 004 phase A2's existing multi-line text editor, with its existing commit rules (click elsewhere or Esc ends it, Enter inserts a newline). A second control switches back to slot view, available only when the current text fits the slot model described above (exactly one `over`, one or more `show`, optionally one `xunit` and/or one `yunit`, nothing else); otherwise that control is unavailable and a short note explains why, and the region keeps showing raw text. Typing or pasting text containing a newline directly into a slot is rejected (the slot keeps its previous committed text and shows a brief message pointing at the raw-text control); only the raw view accepts multi-line input.

### Per-slot error display
A y-slot whose own expression fails (unknown name, wrong shape for the current mode, a syntax error) shows a short error marker confined to that one slot (for example a reddish underline) when the slot is not focused, and the full engine error message (same wording spec 004 already produces, e.g. `show 'Y' needs a single value`) appears near the slot on hover or focus, never permanently over the chart. An error that is not clearly about one y-slot (mismatched units between traces, or anything about `over`/the unit controls) is shown at the x-slot or the relevant unit control instead of at a y-slot. Whether an erroring y-slot's trace is simply left out of an otherwise-drawn chart (true partial preview) or the whole chart stays hidden until every filled slot is valid is **Open question 1** below; this spec's acceptance criteria describe the smaller, GUI-only version (error message attributed to the right slot; see criterion 12) and leave full partial-trace rendering as a follow-up, pending that decision.

A y-slot that refers to the x-slot's sweep name before the x-slot has any valid value (for example typing `sin(x)` while the x-slot is still empty) shows a neutral "waiting for x" hint rather than an error, and is validated normally as soon as the x-slot becomes valid.

### Resize, move, delete, save/reload — unchanged
These behave exactly as today's `PlotRegion` (spec 004 criteria 25-26 and the GUI rules in `gui/regions.py`): `region.set_size`, the resize handle, moving, selecting, and single-owner deletion (the G4 regression) are not redesigned here. The slot layout simply reflows inside whatever size the region has, using the same margins the chart already uses. Saving and reloading store and restore exactly the same `text`/`w`/`h` as spec 004; which view (slots or raw) is shown after reload is re-derived from the stored text (see Mapping), it is not itself saved.

## Syntax proposal (own keywords)
No new engine syntax. The compiled text uses only spec 004's existing keywords (`plot`, `over`, `show`, `xunit`, `yunit`) in the fixed order given under Mapping. No new statement kind, no change to `livesheet/engine/syntax.py`.

## Acceptance criteria
GUI-level; `P` means the plot region's compiled text and `region.result.plot` after both slots are committed. References to "criterion N of spec 004" mean `docs/board/specs/004-plots.md`'s numbered acceptance criteria and reuse its exact sheets/numbers.

Fresh region and growth
1. A freshly inserted plot region shows exactly one empty y-slot (with a hint) and one empty x-slot (with a hint); no axis lines, ticks, grid, unit control or error message are drawn.
2. On the sheet of spec 004 criterion 1 (`v := 3 m/s`, `t := 0 s to 10 s step 2 s` above the plot), typing `t` into the x-slot and `v*t` into the y-slot and committing both (Tab out of each) compiles to `plot\nover t\nshow v*t` and gives a `PlotData` identical to criterion 1's (same x, y, units, labels, limits, ticks).
3. On an otherwise empty sheet, typing `x from 0 to 6.283185307179586 points 5` into the x-slot and `sin(x)` into the y-slot gives a `PlotData` identical to criterion 4 of spec 004.
4. After criterion 2's plot is valid, a second, empty y-slot appears automatically below the filled one. Typing `2*v*t` into it and committing gives a `PlotData` identical to criterion 3 of spec 004 (two traces, `style_index 1`), and a third empty y-slot then appears below that.
5. Filling 20 y-slots is allowed (matching `MAX_TRACES`); no 21st empty slot is then offered.
6. Clicking the x unit control on the sheet of criterion 2 and typing `ms`, then committing, adds `xunit ms` to the compiled text and gives the x side of `PlotData` from criterion 2 of spec 004; clearing the control back to empty removes the `xunit` line and the axis reverts to the automatic unit. The y unit control and `yunit` behave the same way.
7. Clearing the only filled y-slot's text back to empty returns the region to the state of criterion 1 (hint only, no chart), without affecting the x-slot's own committed content.
8. Partial state: the x-slot is filled and valid (`t`, with a definition above as in criterion 2) but no y-slot is filled: no axes, ticks or chart are drawn; the one (trailing) y-slot shows its hint; no error is shown (this is a GUI-incomplete state, not the engine's "needs a 'show' line" error from criterion 13 of spec 004).

Keyboard and commit
9. Tab inside a y-slot commits it (invalid text is kept as typed, not rejected, exactly like a math region's free text) and moves focus to the next slot in the fixed order (next y-slot, trailing slot, x-slot, wrapping back to the first y-slot); Shift+Tab moves in reverse.
10. Enter inside any slot commits it and moves focus the same way Tab does; it never inserts a newline into a slot.
11. Clicking a different slot commits the one being left; clicking outside the plot region commits the slot being edited and deselects the region.
12. Esc while editing a slot reverts only that slot to its last committed text; other slots are unaffected.

Per-slot errors
13. On the sheet of criterion 4, changing the second y-slot's text to `Y` (an undefined name) shows that slot's own error marker and, on focus/hover, the message `Y is not defined`; the first y-slot keeps showing its own marker-free, valid state.
14. A unit mismatch between two y-slots' expressions (for example `v*t` and `t`, different dimensions) is shown as a note associated with the y unit control, not attached to either individual y-slot.
15. A y-slot referring to the x-slot's sweep name while the x-slot is still empty (for example typing `sin(x)` into a y-slot before the x-slot has any text) shows the neutral "waiting for x" hint, not an error marker; filling the x-slot with `x from 0 to 6.283185307179586 points 5` afterwards validates it normally (criterion 3).

Mapping and persistence
16. The compiled text for any valid slot state is always `plot`, one `over` line, one `show` line per filled y-slot in on-screen order, then `xunit`/`yunit` if set, in that fixed order, and is exactly what is written into `RegionData.text` (`w`/`h` unaffected, no document-format change).
17. Loading a sheet whose plot region's stored text is a plain `plot\nover t\nshow v*t` (spec 004 criterion 1's text, written by a plain-text editor or an older build) opens it in slot view with the x-slot and one y-slot pre-filled from that text and no unit controls shown. Loading a sheet whose plot text also contains `title`, `xlabel`, `xlim` or `ylim` (allowed by spec 004 phase A today) opens that region in raw/text view instead, unchanged from today's single-editor behaviour, with a visible way to see it uses the raw view.

Raw/text fallback
18. The raw-view control opens spec 004 phase A2's existing multi-line editor with its existing commit rules; editing there and leaving continues to work exactly as spec 004 criterion 25 describes.
19. Typing a block of text containing a newline directly into a y-slot or the x-slot (for example pasting a full multi-line plot spec) is rejected: the slot's committed text is unchanged and a brief message points at the raw-view control; other slots are unaffected.

Regression (unchanged behaviour, stated explicitly)
20. `region.set_size`, the resize handle (minimum 200x140, grid-snapped), moving, selecting and single-owner deletion behave exactly as spec 004 criteria 25-26; only the slots' on-screen position reflows with the new size.
21. Save and reload round-trip exactly as spec 004 criterion 21/25 (`text`, `w`, `h` unchanged); which view (slots or raw) is shown after reload follows criterion 17, it is not a saved property.
22. PDF export of a region shown in slot view produces the same chart as spec 004 criterion 27; slots and unit controls are never drawn into the export.

## Edge cases
- Changing the x-slot from a range (`t`) to a vector (`X := [0,1,2,3]` defined above, criterion 5 of spec 004) re-evaluates every filled y-slot against the new x; a y-slot that is still the right shape keeps its trace, one that is now the wrong shape shows its own per-slot error (criterion 13) instead of silently keeping stale data.
- A y-slot or x-slot's committed text that is wider than the slot's on-screen width is shown elided (trailing ellipsis) while not focused, and scrolls to keep the text cursor visible while being edited; slots never wrap to a second line.
- A single-point range or vector (`b := 2 to 2`) in the x-slot plots one point per filled y-slot; drawing that point follows spec 004's existing single-point/dot rule, unchanged.
- Descending ranges and very large/small magnitudes behave exactly as in spec 004 (order from data, nice-axis rule); nothing here changes those numbers.
- A y-slot expression calling a user function defined above the plot (`f(t)`) works exactly as it does in today's text spec.
- Deleting a y-slot that is not the last one shifts the ones below it up by one position (and their `style_index`/colour follow their new position, same rule spec 004 already uses: 0-based order of `show` lines).
- A plot region that is still in raw view (because its stored text has `title`/`xlim`/etc.) can be edited and saved exactly as spec 004 allows today; nothing about this spec removes raw-view capability, it only adds the slot view as an additional, preferred entry point for the common case.

## IP check
Pass, with one flag for the manager/Theo (not a copying issue): per IP-POLICY.md rule 6, placeholder/slot-driven editing of a chart's axis and trace expressions is a known interaction *style* across several engineering-calculation products, not only ours; the underlying idea used here ("an empty, clickable field with hint text until filled in") is itself generic and predates and extends well beyond that category (web forms, spreadsheets, countless editors — see Source inspiration). No vendor software, help text, screenshot, icon, wording, cursor behaviour or exact interaction sequence was read or copied; slot layout, the trailing-empty-slot growth rule, the fixed Tab order, the unit-control design and the per-slot error rules are original to this spec. Recommend a short human/legal sanity check on the interaction *technique* before a public release, separate from (and in addition to) Theo's product-level decision to want it; not legal advice.

## Fits current architecture?
- `livesheet/engine/plotting.py`, `livesheet/engine/syntax.py`, `livesheet/document.py`: unchanged in phases C1/C2. Phase C3's scope (true partial-trace preview) may need one small, additive helper next to `build_plot` that evaluates `show` lines independently for display purposes only; `build_plot` itself and its all-or-nothing contract (spec 004 criterion 19) stay as they are regardless — see Open question 1.
- `livesheet/gui/plotregion.py`: the main change. Replaces the single always-multi-line `_Editor` display with a slot-based layout (a small number of single-line editor items: y-slots, the trailing slot, the x-slot, two unit controls) plus the existing multi-line editor kept available as the raw view. New helper functions analogous to today's `is_plot_spec`/`is_blank_spec`/`engine_source`: something that builds the compiled text from slot values (Mapping section) and something that tries to decompose existing text into slot values, returning "not representable" for anything outside the shape in criterion 17's second half.
- `livesheet/gui/plotview.py`: unchanged; `paint_plot` keeps drawing from `PlotData` only, slots are a separate overlay drawn (or not drawn, when invalid) by `plotregion.py`.
- `livesheet/gui/main_window.py`, `livesheet/gui/worksheet.py`: `Insert > Plot` and "Plot here" now create a region that starts in slot view with one empty y-slot and one empty x-slot instead of the current `STARTER_TEXT` string; no other change to how regions are fed into `Engine.evaluate`.
- Tests: a new `tests/test_plot_slots.py` or `tests/test_gui_plot_slots.py` for criteria 1-22 (Qt parts skip when PySide6 cannot load, as today); existing `tests/test_plot.py` and `tests/test_plot_gui.py` need no changes since the engine and `paint_plot` are untouched. The tester should also launch the real app and exercise: typing into a fresh plot's slots, adding/removing traces by typing/clearing, the unit controls, Tab/Shift+Tab/Esc, switching to raw view and back, and save/reload — on Theo's Mac, not only headless.
